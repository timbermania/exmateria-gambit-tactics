## Dec. 4 held three answers and the ADR wrote down two

1. **Parse-time flip** (dec. 4, 2026-06-24): `y_out = size_z*256 - y_psx` in
   `parse_scenarios.py`. Never built — `parse_scenarios.py` is not the chunk
   producer, and `flip_camera_y_q88` was dormant and has since been removed.
2. **Consumed raw as a pose** (amendment 2026-06-28's closing paragraph). The
   2026-07-02 ENTD amendment then leaned on that carve-out as precedent, so a
   position that was already half wrong was load-bearing for a second decision.
3. **Flipped at runtime** (living doc F19, recorded in no ADR until this fold):
   the camera body's depth via `PsxNum.flip_depth_continuous`, because the ortho
   camera was filming a depth-flipped world from an un-flipped position — a
   constant ~+21px lateral error. Verified to the pixel: Agrias / Ovelia / priest
   at native_par 107.6 / 148.4 / 66.7 against a live PSX screen store of
   107 / 147 / 68.

Reading the pre-fold ADR end to end told you the camera was consumed raw. The
useful distinction the fold preserves is that position 2 is **half** stale, not
wrong: the *body* is flipped (dec. 13), the *yaw* is not (dec. 8), and collapsing
those two into one sentence is what let the reversal go unrecorded.

## The named guard did not run — resolved 2026-09-01

The 2026-06-28 amendment closed with a **Guard** paragraph naming two tests.
Measured 2026-08-28:

- `_test_flip_depth_row` moved to `tests/PsxNumTest.gd`, where it now pins both
  `flip_depth_row` and `flip_depth_continuous`. It runs.
- `_test_walk_to_seats_chirality_flipped` was **renamed to reflect the reversal** —
  `tests/ScenarioSpriteMoveTest.gd::_test_walk_to_consumes_preflipped_rows`, which
  asserts the opposite: rows arrive already flipped rather than being flipped on
  consume.
- `ScenarioSpriteMoveTest` is quarantined red in `tests/skip_tests.tsv` on an
  unrelated facing case (#543), so the whole file does not execute.

So the guard named for this ADR's most-revised decision did not run, and its
quarantine note pointed the reader back at this ADR's depth mirror. That is in
`## Verification` in the ADR rather than here, because it is a live fact about the
suite, not history.

**Resolved 2026-09-01 (#752).** The facing case was never the depth mirror — this
ADR was on the quarantine row by mis-attribution. `ScenarioWorld.set_walking`
carried an `elif "facing_direction" in unit` fallback that wrote a 12-bit
ORIENTATION angle into a slot the real `Unit` declares as a 0..3 enum, so a test
double reading it got 3072 where NORTH is 0. The fallback is deleted (the doubles
take `scenario_set_facing`, the production verb), the skip row is gone, and
`ScenarioSpriteMoveTest` is in `run_all_tests.sh`'s array at 79/0. The guard named
for dec. 5 executes.

## The ENTD facing remap was invisible for a structural reason

The `0↔2` swap was wrong from the start and survived months of side-by-side work
because the **only** calibration reference was the Orbonne chapel cast, and every
chapel unit carries ENTD facing `3` (East) — the one value class a `0↔2` swap
leaves untouched. The rule this produced is now documented where it can act:
`tools/gen_reference_goldens.py` records, per reference scene, which raw facings it
exercises, and says outright that chapel is a *regression* guard and never a
facing-calibration reference.
