THE ONE THAT DOES NOT HOLD is dec.
2's slot count: `GambitList.VISIBLE_SLOTS = 4` and `ensure_fixed_size()` truncates DESTRUCTIVELY (pop_back) to 4 on every roster entry point (Character.gd:419 persistence, Unit.gd:1615, GPUCombatTestBase.gd:469), so a 5th authored gambit cannot survive a save/load.
The encoder's cap really is 5 and scenarios reach it only because GambitScenarioRunner passes RAW arrays and never builds a GambitList — a two-tier authored surface.
On the roster path slot 4 is therefore always the encoder's null pad: 16 ints/unit of permanently dead buffer.
This is NOT drift — VISIBLE_SLOTS=4 arrived with the initial import 2026-05-24 and the ADR was accepted 2026-06-17, so the '5 authored slots' framing was already wrong the day it landed.
What dec.
2 actually secured, and what holds, is the INVISIBILITY.
UNDOCUMENTED INVARIANT the decision silently depends on: `GambitList._create_empty_gambit()` pads with 'Always: Wait on Self', which under rule A1 ALWAYS MATCHES — if it reached the buffer the pass would terminate on it and the safety net would be dead for every under-filled unit.
It doesn't only because both host paths filter on `Gambit.is_empty()` (Gambit.gd:271), whose four conditions are exactly the pad's shape.
The pad and the predicate must move together, and NEITHER guard is positioned to catch a break: GambitSafetyNetTest exercises only the encoder, and B-SAFETYNET feeds a raw array that never sees a GambitList pad.
