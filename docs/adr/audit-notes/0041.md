# ADR-0041 audit notes

Audited 2026-08-28, during the de-amendment pass (two dated addenda folded).
Graded against `addons/exmateria_battlefield/camera/PlayerCamera.gd`,
`addons/exmateria_battlefield/cursor/CursorController.gd`, and the takeover
tests — not against the ADRs that cite this one.

## Verdict

`complete`. All five decisions ship. Two ship in their *reversed* shape, which
is now the body text: `_saved_global_pos` was deleted and restored as the
no-cursor fallback, and `request_takeover`'s param was widened from `Node` to
`Object`. Both attempts survive as shipped-then-reversed clauses under
**Considered options**.

## Claims corrected in the fold

- **"`_saved_global_pos` is retired — the field is deleted."** False since
  commit 04d8e22a. It is at `PlayerCamera.gd:132` and read at `:545`, on the
  no-cursor branch only. Dec. 2 now states the field's real role.
- **"The four `Avoid` clauses on the Takeover-mode glossary entry have hard
  enforcement at the call sites … because the field they would set is gone."**
  Wrong twice: the entry carries **three** `Avoid` clauses, and the field is
  back, so the enforcement is not the field's absence. The Consequences bullet
  now names the actual enforcement (the mode gate, plus `_follow_has_target`
  winning whenever a cursor has pushed).
- **"`PlayerCamera.follow_cursor(world_pos)` — pushed by the cursor's
  `cursor_moved` signal — is what advances the body, period."** The push path
  is now `track_cursor(tile_world)`, which clamps through a deadzone scroll box
  (`_deadzone_focus`) and calls `follow_cursor` only when the tile would leave
  the box. `follow_cursor` remains the direct entry for the seed snap and the
  Q/E recenter. The deadzone is documented in `docs/context/29-battlefield-camera.md`
  and has no ADR of its own; it does not disturb the authority rule, because
  the only tile the camera ever re-delivers is the last one the cursor pushed
  (`_last_tracked_tile`).
- **"`EffectViewerScene` extends `Node`."** It extends `Node3D`
  (`src/scenes/EffectViewerScene.gd:1`). The argument is unaffected — the
  `Node` typing failed on `CinematicManager`, which is `RefCounted` — but the
  illustration was wrong. `PlayerCamera.request_takeover`'s docstring repeats
  the same imprecision; true by inheritance, so not filed as a defect.
- **"a host scene that instantiates a `TileCursor` must call
  `follow_cursor(initial_world_pos, true)` on first placement."** That wiring
  moved into `CursorController.seed_from_map()`; hosts choose the timing, not
  the call.

## Left open

Dec. 5 is a negative — `PlayerCamera` holds no cursor reference and does not
poll one. It is true today (no `get_node`/`find_child` for the cursor anywhere
in `PlayerCamera.gd`; `_follow_target` is written only by `follow_cursor` and
`track_cursor`) but nothing asserts it, so a future reach-in would land silently.
Proposed guard is in the register's `proposed_guard` column.

`ADR-0137:141` and `FormationMapHost.gd:520` both describe the release ease as
lerping to `tile_cursor.active_tile`. That is the right *value* by the wrong
*mechanism* — the camera lerps to `_follow_target`, which the cursor pushed.
Left alone here; ADR-0137 is still on the burn-down.
