# ADR-0088 — audit note

*Verified 2026-08-28. ADR-level verdict: `half-landed`. **BLOCKED** under the
skill's "a question blocks the file" rule — the de-amendment rewrite is held for
the author. Both readings are recorded below; the ADR itself was not rewritten.*

## Why this file is blocked and not folded

ADR-0088 is 850 lines over six amendments, and folding it means writing one
normative sentence where decision 7 item 2 stands. That clause names **one
tracked shrink-only allowlist file**. The tree has two carriers for the same
answer, and choosing which one the folded ADR states is a product call about a
tracked artifact, not a reading the code settles. Guessing would delete the
evidence for the other reading in the same commit — the asymmetry the blocking
rule exists for.

Everything else in the ADR is decidable from the tree (see "What the tree says"
below), so the block is one clause wide. It is still a block: the rewrite is
one document, and this clause is in it.

## The question

**Decision 7 item 2 says the registration-audit allowlist is a tracked file that
may only shrink. What is the allowlist?**

- `config/ui3_registration_allowlist.json` is tracked and **empty**
  (`{"classes": []}`).
- `UI3RegistrationAudit.check(ui_root, allowed_classes)` takes the list as an
  **argument**, and enforces shrink-only *two-sidedly per audit root*: an
  unlisted violation fails, **and** a listed class with zero violations fails
  ("remove it — shrink-only ratchet"). Nothing diffs the tracked file across
  commits; the ratchet is a runtime property of one root's argument.
- Two consumers pass the tracked file (`EquipPickerFrameGroupTest.gd:113`,
  `StartMenuFrameGroupTest.gd:108`). Four pass a local const or a literal
  (`DetailRegistrationAuditTest.gd:25` `ALLOW := []` and `:33`
  `EMPTY_DERIVED_ALLOW := []`, `ChangeJobTitleElementTest.gd:120`, and the two
  synthetic roots in `UI3RegistrationAuditTest.gd` /
  `UI3ScreenAnchoredAuditTest.gd`).

So the outcome matches the decision and the **mechanism does not**, and a
reviewer diffing the tracked file sees nothing when a local list grows.

**Reading A — the tracked file is the allowlist.** Rework `check` to per-root
semantics, key the JSON by audit root, and migrate the two local consts into it.
Decision 7 item 2 then means what it says, and shrink-only is visible in one
reviewed file. Cost: a schema change plus two migrations.

**Reading B — a reviewed const is the allowlist.** Accept per-test lists as the
mechanism and restate decision 7 item 2: a local const is also a code change a
reviewer sees, which is the argument `DetailRegistrationAuditTest.gd:24` already
makes in prose. Under B the tracked file should be **deleted**, not left empty —
an empty tracked ratchet is the misleading artifact.

A third reading — bless the coexistence, "the allowlist is whatever the audit
call is handed" — is available and is *also* a choice, not a description. It is
recorded here so the answer can pick it deliberately rather than by default.

The tree does not settle it. `DetailRegistrationAuditTest`'s note calls the state
provisional ("until that per-root semantics is reworked"), but that was written
2026-08-12 and nothing has moved since.

## Second finding, same decision — coverage

`UI3RegistrationAudit.check` / `check_empty_derived` / `violations` are called
from exactly six files, listed above. Amendment 4 audited **five** registered
screen classes; `FormationScene` is the one with **no** boot-time registration
audit — and it is precisely the screen Amendment 5 was written about. No
`tests/Formation*.gd` calls the audit at all.

## Proposed guard arms

1. **(decision 7)** Assert every class that registers a root element has at
   least one test calling `UI3RegistrationAudit.check` on it — static,
   grep-level over `tests/`. This is the arm that would have caught
   `FormationScene`.
2. **(decision 7, after the question is answered)** Assert the tracked allowlist
   has exactly one meaning: either it is the only allowlist (reading A) or it
   does not exist (reading B). Today it is neither. Do not build this arm before
   the answer — it would ratify a reading nobody chose.

Recorded so the rewrite does not re-derive it.

  `tools/check_location_ownership.py` runs green as a pre-flight gate from

  `UIUnitNameplate` extend `UI3Element` directly; `UIUnitInfoWindow` reaches it

  none`; `UI3Element.Frame` is `{ NONE, MENU_TILE, STRIPE }` — there is no

  Amendment 1 contradicts on the next page.
- **One shipped decision the ADR never records.** `UI3OwnerMapPicker` +
  `assets/shaders/ui3_owner_color.gdshader` + `UI3OwnerPickTest` /

- **Amendment 6 §5 cites "Amendment 1 decision 12".** Amendment 1 has six items.
  The pointer is dangling; the claim it makes ("`UI3RegistryView` remains a pure
  view") is Amendment 1 §6.
- **Not mechanizable.** Decision 1 ("an element is a logical part") is a human
  judgement — which is why the Amendment 6 ownership map exists at all.
