## The self-contradiction is resolved by the tree, not by a choice

Addendum 3's own Decision paragraph said `template_token` "is therefore carried by
exactly the 21", while its Conformance paragraph twelve lines later said the 15 story
bodies and 3 monster sheets "keep their token for now". A reader who stopped at the
first sentence would read the guard as failing.

This is not a fork the rewrite had to pick between: the tree already answers it.
`AllTemplatesSeederTest._test_no_wardrobe_sheet_is_minted_as_an_appearance_type`
asserts `tokened == 39` and writes the number down as a one-way ratchet that "may only
go DOWN, and only by retiring the remainder"; a sibling assertion pins the job-reached
share of that population at exactly 18. Dec. 8 now states the 39 = 21 + 18 in one
place, with the staging as part of the decision.

## The predicate the code implements is the narrow half of the one the prose stated

Addendum 3 stated the test as "no job's `body_sprite_id_male`/`_female` resolves to it"
— *any* job. `JobDatabase.generic_wardrobe_sprite_ids()` iterates only jobs where
`is_generic_human(job)` holds, so it answers "no **generic-human** job reaches it".

That gap is the staging, not a defect: the 18 remainder are reached by `special` and
`monster` jobs the narrow predicate cannot see, so widening the predicate and retiring
the remainder are the same act, and the ratchet is the instrument that would report it.
Dec. 8 says both halves now, because only the prose sounded finished.

Scope, also folded in: `_is_generic_wardrobe` is applied in `AllTemplatesSeeder` only.
It gates *minting*, not resolution — the resolver has no wardrobe check — so the
invariant is "no seeder mints a wardrobe sheet with a token", not "a token on a
wardrobe sheet is rejected". A hand-built `Character` can still carry one.

## Addendum 2's own breakdown line was stale in its middle term

It read "59 uniques + 77 generic-human appearances + 55 renderable monster jobs". The
77 folder rows have since split into 39 folder-sourced appearance rows and 38
**job-sourced** wardrobe rows (`AllTemplatesSeeder._generic_human_job_variants`), which
is dec. 8's correction arriving in dec. 7's territory. Dec. 7 now lists **four** variant
sources rather than three. The 59 and the variant axis both still hold
(`_test_all_uniques_resolve_via_unit_names`, `_test_roster_enumerates_every_variant_exactly_once`).

The `~191` total is dropped rather than refreshed: no suite asserts a roster size — the
axis test compares against a recomputed expectation — so the number could only rot.

## References graded

ADR-0072 is extended, not reversed, exactly as the Status line claims: its dec. 1
unique-vs-job-routed dispatch is still what runs under the token branch, and dec. 8's
whole argument is that a token on a wardrobe sheet *defeats* ADR-0072 dec. 1 — a claim
that only makes sense if dec. 1 is live. ADR-0013's decode-at-parse discipline holds for
dec. 4: the `sprite_id → token` table exists only in the Python transform, and no
GDScript file references `GENERIC_SPRITE_NAMES`. ADR-0066's identity rule (cited to
reject the slug-as-router option) is intact — `slug` and `template_token` are separate
fields on `Character`, and the catalogue namespaces its slugs rather than overloading
the token.

## No open question

The one thing this ADR declines to answer is stated in dec. 8 and stays open by design:
whether a story body lacking a `special_name` binding is a bucket of its own. It does not
block the fold — nothing in the rewrite depends on the answer, and the 18 are named
either way.
