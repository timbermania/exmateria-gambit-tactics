# ADR-0009 — audit note

Folded 2026-08-28. Verdict **half-landed**: decisions 1–2 and 4–8 built, decision 3 carries
six outstanding violations booked as debt (#363). This file replaces the working-input note
the 2026-08-28 audit left behind, which asked to be deleted once the rewrite consumed it.

## What the fold did

This ADR carried **three** dated blocks and two spellings of "amendment": `## Addendum
(2026-06)`, `## Addendum (2026-07)` with an unnumbered `> **Amendment (#228 Phase 3,
2026-07-29)**` nested inside it, and `## Amendment 3`. The previous audit declined to
renumber them because renumbering a dated heading is citation-breaking. A fold deletes all
three, so every citer is retargeted in the same commit — the ADR-0077 case law.

| block | class | disposition |
|---|---|---|
| `## Addendum (2026-06)` — projectiles | says "no new decision" outright, but its **trap** is a rule | the trap ("granularity is primitive count, not node-ness") is folded into **dec. 4**; the projectile paths join the per-face / per-object bullets in Consequences |
| `## Addendum (2026-07)` — "Two keys from one model (#212)" | **a new decision** — occlusion and fold order are different quantities, which nothing above had said | promoted to **dec. 6** |
| the same addendum — "within-bucket order is the age tie-break" | **a new decision** — it replaces #214's reverse-submission rule | promoted to **dec. 7** |
| the same addendum — "the reversed-Z projection-source rule" | **a new decision** — it is the rule that forbids a whole class of refactor | promoted to **dec. 8** |
| the same addendum — "three renderings of the one formula" | how they learned it | the surviving two copies and their single-sourced calibration are one Consequences bullet |
| the same addendum — the `.glsl` exemption paragraph | a guard that exists | the exemption *mechanism* is now stated in dec. 3; the `.glsl` instance is gone |
| `> **Amendment (#228 Phase 3)**` | already-built retirement | the retirement is stated in the surviving-copies bullet; the copy it retired is not described as live anywhere |
| `## Amendment 3` | grading, not rules | deleted; its corrections are applied below and its per-decision table is the register |
| the "Migration is incremental" bullet | transient migration plan, built | deleted |

The 2026-07 addendum said "**No new decision**" about itself. That is the one classification
the fold overrules, and on the addendum's own evidence: it introduced a second derived key
because sharing one collapsed every prim into a single bucket (#212 was a *bug fix with a
new rule*, not an application of an old one), a within-bucket ordering key that explicitly
overturned #214's, and a projection-source rule that retired a proposed refactor. Three
rules nothing above it stated. They are decisions.

## Corrections applied

Measured against the tree, not against the prose:

| the ADR said | the tree says |
|---|---|
| `psx_ot_depth(world_point, proj, view, inv_view, mode)` | four parameters — `psx_ot_depth(vec3 point, mat4 proj, mat4 to_view, int mode)`; `view`/`inv_view` collapsed into `to_view` |
| defined in `assets/shaders/psx_ot_depth.gdshaderinc` | `addons/exmateria_schema/compositing_key/psx_ot_depth.gdshaderinc` (ADR-0146, prologue pass 6) |
| the source of truth is a script under `src/core/` | `addons/exmateria_schema/compositing_key/DepthMode.gd` — the 2026-07 addendum repeated the stale directory a second time |
| "the six modes" trace to `0x801aa54c` | `DepthMode.Mode` has **ten**. 0–5 are the ROM switch; 6–9 (`UNIT`, `TILE_OVERLAY`, `MAP_SKIRT`, `SHADOW`) are project nudges with no ROM bucket offset — and two of the four were named in this ADR's own migration bullet, so the count was inconsistent the day it was written |
| `GODOT_UNITS_PER_OT_BUCKET` | `UNITS_PER_OT_BUCKET`, and its value is settled: **0.19** |
| "Two keys from one model" | four derivations hang off the calibration — `ot_depth`, `ot_order_z`, `render_layer_order_for`, `rung_z`; `DepthMode.gd` says so itself. The calibration is still single-sourced; only the count was stale |
| Amendment 3: "24 shaders `#include` the new path" | **21** files `#include` it directly (a 22nd match is the seam quoting its own usage line in a comment). The three `unit*.gdshader` entries reach it transitively through `unit_sprite_body.gdshaderinc` |
| Amendment 3: the age cases are at `OTDepthPrimOrderTest.gd:124` and `:127` | both of those lines are *depth-beats-age* assertions; the two cases are the functions `_test_prim_order_age_tie_break` and `_test_prim_order_depth_separates_over_age` |
| ADR-0015 is "still *Proposed*" | its Status opens `Proposed (2026-06-03)` but closes "**accepted-as-amended**". The supersession claim itself is sound and code-backed |

Verified good and carried forward unchanged: every claim of the #228 Phase 3 amendment
(`combat_displayspace_composite.glsl` and `CombatDisplaySpaceCompositeTest` are both gone;
`effect_fold_add`/`mix`/`sub` reach the seam through `effect_particle_fold.gdshaderinc` →

GDScript copy's "no production caller" — the only callers of `DepthMode.ot_depth` in the tree
are in `tests/DepthModeTest.gd`, which is exactly the CPU-oracle role claimed for it.

## The recorded question, and where it now lives

The previous audit recorded a question it declined to guess: are decision 3's six
`src/ui3/shaders/` violators **debt** (they are on `BURN_DOWN`) or **exemptions** (their
same-directory neighbours `vitals_bar`, `vitals_sprite`, `menu_cursor_shadow` have the
identical ADR-0077 rung-Z rationale and took the `psx-ot-depth-exempt:` marker)?

It did not block this fold, because the tree already answers what the *state* is even though
it does not answer which they *should* be. `check_depth_shaders.py`'s own comment and issue
**#363** say it outright: "**The `BURN_DOWN` list makes no claim either way.** Working it
means, per file: decide *exempt* or *route*, then delete the line." So the now is: six
`DEPTH` writes outside the seam, unclassified, listed rather than exempted, tracked. The ADR
states exactly that and asserts neither reading; both readings stay in the register and in
#363, and nothing supporting either was deleted.

The second, lower-stakes question — that "ADR-0009 amendment N" was ambiguous by
construction because the file spelled amendments three different ways — is dissolved rather
than answered: there are no dated blocks left to be ambiguous about.

## Open

- **Decision 3's six violators need a per-file *exempt or route* call.** #363. Until then the
  ADR-level verdict stays `half-landed`.
- **`DepthMode.ot_depth` has no production caller.** That is by design (it is the CPU oracle
  for the shader copy) and is stated as such, but it means the readable spec and the shipped
  formula agree only through `DepthModeTest` — worth remembering if that test is ever
  narrowed.
