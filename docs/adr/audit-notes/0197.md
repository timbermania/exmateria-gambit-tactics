The 2026-08-28 amendment kept a date rather than a number because the 2026-08-13 heading
was cited from source as a bare "ADR-0197 amendment" and renumbering a dated heading is not
additive. That constraint is discharged, not worked around: a **fold deletes the heading**,
so every citer is retargeted in the same commit. This is the ADR-0077 case law.

## The recorded question, and why it did not block

The 2026-08-28 amendment recorded two readings of the 48-job drop and declined to choose:
**(a)** it is hygiene below the decision, so "every job" is loose prose; **(b)** it is a
catalog-content rule inside dec. 3, so dec. 3 is wrong as written.

The skill's blocking rule covers a question you *cannot answer* — one whose answer picks
between designs, where a wrong guess ships a confident document for a design nobody chose
with the other reading's evidence deleted beside it. This is not that. **Both readings
describe the same code**, agree on why the 48 drop, and imply no different build. What they
disagree about is whether the ADR says so.

A rewrite that states the now cannot preserve reading (a)'s practical consequence, because
(a)'s consequence is *silence* — dec. 3 keeping the word "every" while 48 of 160 jobs never
appear is a decision that does not state the now, which is the one thing this operation is
for. So dec. 3 states the drop **and** states (a)'s substance in the same breath: it is data
hygiene, not a progression gate, and decision 1 still holds. Nothing either reading asserts
is lost; only the option of not mentioning it.

## Corrections applied to the prose

- **The row range was stale at both ends.** "24 to 160 rows" is now **23 to 51**. 160 was
  never reachable even on the day it was written — the 48 drops are exactly where the
  amendment's own "112" comes from — and the low end counted 24 Movement *records* rather
  than the 23 rows that survive the pad drop. The purpose is unharmed: 51 rows still
  overflow a 5-row window, and `FormationAbilityPickerTest` asserts `row_count() > 5` rather
  than a literal.
- **"Holy Sword is shared by Delita, Agrias, and Wiegraf" counted characters.** **Five** job
  ids carry that skillset — `0x05`, `0x1e`, `0x34` as "Holy Knight"; `0x20`, `0x28` as
  "White Knight". The rule is untouched (all five are non-generic, so lowest-id picks `0x05`,
  which the guard pins), but a reader checking it against `jobs.json` would not find three.
- **"Mirrors the equip picker" is true about the gate, not the order.** `EquipCandidates`
  carries the claimed shape — `build_catalog` = every slot-legal item with ownership
  ignored, ROM-faithful `build` retained beside it — but sorts descending by item id where
  this catalog is name-ascending. The Context paragraph now scopes the word.
