## The two recorded questions

**Decision 4 — "closed by default" — did not block, and is not really two readings.** The
previous audit asked whether persisting `was_visible` means dec. 4 *held* (the default is
still closed; visibility joined the position/size layout the decision already persists) or
was *superseded* (the decision speaks about game launch, and at launch the answer is now
"whatever you did last time"). Both readings describe the same behaviour and imply no
different build; they disagree only about the label. A rewrite that states the now settles
it by stating the behaviour instead of labelling it: position, size **and** visibility
persist, the first-run default is closed (`DEFAULT_DEBUG_WINDOW`), and the rejected
"Always-open dashboard at game launch" option stays rejected because the dashboard cannot
appear on a start where the user did not leave it open. That is what the code does, and it
is what both readings agree it does.

**Decision 2 — the per-category cell collapse — is a genuine open call, and is filed rather
than guessed.** `DebugDashboard.set_category_collapsed` hides a whole cell behind a `▶`/`▼`
button, persisted as `UserSettings.debug_window.collapsed_categories` and restored on boot.
No decision reaches it: dec. 6 is scoped inside one panel's body, dec. 7 to panels within a
cell, dec. 8 to whole surfaces. It is a fourth fold layer, and the closest thing in the tree
to problem (1) this ADR was written to retire — differing in that it is opt-in and persistent
rather than exclusive.

This did **not** block the fold, on the same ground as ADR-0009 dec. 3: what is disputed is
whether a shipped behaviour *conforms*, not what any decision *says*. Conformance is the
register's and the tracker's business. So dec. 2 keeps its rule, the Consequences state the
collapse as fact with the enum doubling as its visible cause, Verification states both
readings without choosing, and #686 carries the call. Nothing supporting either reading was
deleted.

The visible cause is measurable: `Category` has grown from the **11** the Context enumerates
to **22** (`DebugOverlay.TAB_NAMES`), and the list is still named `TAB_NAMES` — a noun this
ADR retired.

## Corrections applied

| the ADR said | the tree says |
|---|---|
| masonry is "N uniform-width columns sized from `container_width / min_column_width`" — width fixed, count derived | the reverse: column width is the widest visible cell clamped into `[min_column_width, max_column_width]`, and the count follows. `max_column_width` (default 600) did not exist in the decision. The **packing** rule dec. 2 actually argues for — shortest column at the moment of placement — is unchanged |
| "~20 existing call sites" for `create_collapsible_section` | **38**. The drift is in the ADR's arithmetic, not in the rule |
| "the dashboard is closed by default at game launch" | it reopens iff it was open at last quit; the *first-run* default is closed |
| dec. 5's boot sites | all seven still exist and still call the API. `MapComposer.gd` moved to `addons/exmateria_battlefield/assembly/`, which costs the rule nothing because it names the file, not its path |

Verified good and carried forward: dec. 1 exactly (`_dashboard: Window`,
`window/subwindows/embed_subwindows=false`); dec. 3 exactly — the third parameter is
literally `_start_open`, underscore-prefixed and unread, which is the no-op the decision
promised rather than a silently honoured toggle; dec. 6 held its scope, with `add_fold_section`
having exactly one consumer panel; dec. 5's five methods all present and `switch_to_tab`
being `_dashboard.scroll_to_category`, the scroll the Consequences promised; and the
`_gui_input` shim still present as the harmless no-op the Consequences said to leave.
