## The fourth axis, and why recording it here is not a guess

`deploy_active` has its own field, its own setter refresh, and a code comment crediting
**ADR-0042** for the widening ("Widens the tick gate + the visuals-freeze predicate so
deploy marches animate"). ADR-0042 contains no occurrence of `combat_visuals`,
`deploy_active`, or the word "freeze" — so before this fold the axis was documented in a
`CombatLoop` comment and nowhere else. ADR-0082 corroborates the *reason* from a third
place: "ADR-0042 had already established that the simulator can tick with `combat_active`
false in a non-combat phase."

So the split is clean and needed no judgement call: ADR-0042 owns the phase and the tick
gate, this ADR owns the freeze predicate, and the axis is recorded where the predicate
lives. Amendment 3 predicted this shape would recur and it is the second instance —
Addendum #1 wrote the prediction down ("an orthogonal predicate input, a setter or signal
that retunes the group"), and the mechanism has held both times. Only the bookkeeping
lagged, which is now stated in the Consequences as the recurring cost.
