# ADR-0018 audit notes

Audited 2026-08-28, during the de-amendment pass (one addendum and one amendment
folded). Graded against `src/gpu/GPUCombatInterpreter.gd`, `src/gpu/CombatLoop.gd`,
`src/gpu/CombatHost.gd`, `src/gpu/shaders/combat_common.glslinc`,
`tests/GPUCombatTestBase.gd`, and `tests/GPUCombatInterpreterTest.gd`.

## Verdict

`complete`. The shape this ADR decided is built and standing. Two decisions ship in a
shape the body contradicted; both are now the body text, with the original under
**Considered options**.

## Numbering

The addendum's four lettered boundary decisions (A1–A4) are promoted to decisions
8–11 in order. No `ADR-0018 A4`-style citation existed to break; the one anchored
citation to the addendum — `src/gpu/CombatLoop.gd:33`, "Per-event semantic signals
(ADR-0018 addendum)" — is retargeted to `dec. 9` in the same commit.

Decision 6 ("Migration is staged, tests green at each step") is **deleted**, not
restated. It is a three-landing staging plan, all three behind us, and a staging plan
cannot be re-checked against a tree that only shows the end state. Its number is
retired rather than reused — decision numbers here are append-only and gap-tolerant.

## Claims corrected in the fold

- **Decision 1's event vocabulary is not the enum that shipped.** The ADR named nine
  types; `EventKind` has nine; six overlap. `CastEnded`, `ChargeBegan` and
  `ChargeEnded` never landed — charge VFX is driven from `CombatLoop` off
  `STATE_CHANGED`. `MpSpent` shipped as `MP_CHANGED`, which reports any MP difference
  rather than only spending. Three types the ADR never named carry real load:
  `POSITION_CHANGED`, `STATE_CHANGED` (it carries the transition dec. 2 says a cast
  informs), and `ACTION_COMMITTED` (added at #93 as a commit witness independent of
  host-frame sampling, and it fires for a pure attack as well as an ability). Dec. 1
  now states the shipped enum; the three that never landed are under Considered
  options with the reason.
- **A4 was reversed through its own escape clause.** A4 decided "independent sibling
  hosts, no shared base" and named the very class that now exists: "a `CombatHost`
  base would just re-introduce the shared-base coupling C8 removes."
  `src/gpu/CombatHost.gd` is real and **both** hosts `extends` it. This is A4's
  closing "extract one later only if real duplication appears" being exercised — the
  duplication was the accessor surface both hosts had to re-expose once tests began
  subclassing *each* host. Dec. 11 states the base as it ships, with the
  mechanics/policy constraint that was what the original rejection actually protected.
  Verified here: the `extends` relationship, and that the base's contents are
  accessors and holders. **Not** re-derived: that the policy split is complete — that
  is the file's own docstring claim, and nothing asserts it.
- **"`UNIT_SIZE` 85 → 86" is a delta, not a current fact.** `U_CAST_STEP_ID` is still
  at offset 85, and `UNIT_SIZE` now declares 98 — the struct kept growing long after
  this ADR. Dec. 4 says so explicitly now, because the bare "85 → 86" reads as a
  layout claim a parity check would fail.
- **"~25 GPU tests" is 74.** 74 files `extends GPUCombatTestBase` today. The number is
  worth keeping because it is the standing evidence for dec. 5's byte-identical-hook
  promise: the surface held through the migration and well past it. (A prior grading
  pass recorded 73; the current count is 74.)
- **Decision 4's latch is sanctioned, not drift.** `_spell_cast_active` is a live
  Dictionary on `CombatLoop` (`:195`). Dec. 4 explicitly kept it in the pump for its
  animation-playback role and retired only its detection role. A reviewer finding a
  CPU latch beside a GPU step-id should read dec. 4 before filing it.

## Filed as an issue, not fixed here

**#676** — `GPUCombatInterpreter.gd`'s class docstring still says the cast/charge
events "land in a later slice; until then `_process_spell_cast` / state-transition
stay in the caller." The cast half landed: `CAST_BEGAN` and `ACTION_COMMITTED` are
emitted from that file, deduped against `cast_step_id` exactly as dec. 4 designed,
with three test arms on `CAST_BEGAN`. `STATE_CHANGED` is emitted there too. Only the
*charge* half is still caller-side. The sentence was accurate when written and
describes a tree two slices old; it reads as a live TODO and sends a reader to the
wrong file.

## Left open

Dec. 11's mechanics/policy split is unasserted. The base is one accidental `signal`
or `on_*` hook away from being the policy-bearing `CombatHost` the original A4
rejected, and nothing would report it. Proposed guard is in the register's
`proposed_guard` column.
